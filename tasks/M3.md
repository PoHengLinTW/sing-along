# M3 — Hardening and Deploy

**Goal:** Enforce the storage caps, clean up orphaned uploads, polish error handling, and deploy to the homelab behind Cloudflare Tunnel with R2.

**Exit criteria:** The app runs at `https://<your-domain>` against real R2, the caps are enforced, and the Playwright smoke flows pass in CI.

---

### M3-01 Caps configuration and server enforcement
**Depends on:** M1-05
**Scope:** Enforce every PRD §5.9 cap on the server, with limits set through env vars (defaults as in the PRD).

**AC:**
- [x] upload-url rejects:
  - `sizeBytes > 60 MB` → 413
  - `durationMs > 10 min` → 422
  - a project that already has 10 tracks (active + pending) → 409
  - a global total (active + pending `size_bytes`) + new file > 8 GB → 507
- [x] `POST /projects` rejects a new project once 100 exist → 409.
- [x] Every rejection returns a machine-readable `code` (e.g. `TRACK_LIMIT`, `STORAGE_FULL`) and a human-readable message.
- [x] Checks and inserts run in a transaction (or under an advisory lock), so two uploads at the same moment can't both push past a cap.
- [x] Unit tests cover each cap at, just under, and just over the limit.

### M3-02 Storage usage endpoint and home-page indicator
**Depends on:** M3-01, M1-08
**Scope:** `GET /api/storage` returns bytes used and the limit, plus the project count and limit. The home page shows the storage used.

**AC:**
- [x] The endpoint returns `{usedBytes, limitBytes, projectCount, projectLimit}`. `usedBytes` counts active tracks only.
- [x] The home page shows e.g. "5.2 / 8 GB used" with a bar that turns amber at 80% and red at 95%.
- [x] The indicator refreshes after uploads and deletes.

### M3-03 Cap-aware UX
**Depends on:** M3-01
**Scope:** Show the caps in the UI before users run into them, and turn server rejections into clear messages.

**AC:**
- [x] Oversized files (> 60 MB) and files over 10 min are rejected **on the client** before uploading, with messages naming the limit. WAV files get the hint "convert to FLAC or MP3."
- [x] At 10 tracks (drafts don't count), the upload button is disabled with a tooltip "Track limit reached (10)." Recording is still allowed, but uploading the draft shows the limit message.
- [x] A `STORAGE_FULL` rejection shows "Storage full (8 GB) — delete old tracks or projects."
- [x] At 100 projects, "Create project" is disabled with an explanation.

### M3-04 Orphan and pending cleanup job
**Depends on:** M1-05
**Scope:** A nightly job, run in the API process with a scheduler such as `node-cron` or croner, that deletes stale pending tracks and orphaned storage objects.

**AC:**
- [x] It deletes `pending` tracks older than 24 h, along with their storage objects if present.
- [x] It lists the bucket's objects under `projects/` and deletes any with no matching DB row that are older than 24 h.
- [x] A `--dry-run` CLI command (`pnpm cleanup --dry-run`) logs what would be deleted without deleting anything.
- [x] Each run logs counts (pending removed, orphans removed, bytes freed).
- [x] Unit tests use a mocked storage client and a test DB.

### M3-05 Error, loading and empty-state pass
**Depends on:** M2-09
**Scope:** Check the flows touched in M1 and M2 for consistent loading states, error recovery and empty states.

**AC:**
- [x] Every data fetch has a loading state and an error state with a retry button. No blank screens.
- [x] When an audio download fails, the track shows "Failed to load audio — Retry" and the rest of the project still plays.
- [x] An expired presigned GET URL is refreshed and retried automatically once.
- [x] A project with no tracks shows an empty state with "Upload a track" and "Record" actions.
- [x] The API has a global error handler that logs details on the server and returns a generic 500 message to the client (no stack traces).

### M3-06 Production Docker image
**Depends on:** M1-01
**Scope:** A multi-stage Dockerfile that builds the web and api apps. Fastify serves the API under `/api` and the built web assets with SPA fallback.

**AC:**
- [x] `docker build` produces a single image under 300 MB that runs as a non-root user.
- [x] `/api/*` goes to the API. Other paths serve static files, and unknown paths fall back to `index.html`.
- [x] Static assets with a hash in their name get `Cache-Control: immutable, max-age=31536000`. `index.html` and the service worker get `no-cache`.
- [x] Database migrations run automatically on container start, before the server starts listening.
- [x] `GET /api/health` returns 200 when the DB is reachable and 503 otherwise.

### M3-07 Production Compose stack with Cloudflare Tunnel
**Depends on:** M3-06
**Scope:** `docker-compose.yml` with app, postgres (on a named volume) and cloudflared, configured through `.env`.

**AC:**

- [x] Postgres data survives `docker compose down && up`.

### M3-10 E2E for M1, M2 and M3 user flows (Playwright, in CI)

It replaces the three smoke flows this task first listed; those are the tests marked **(orig. flow n)** below.

**AC:**
- [x] Every flow below has a test. Flow to test (`file › test`):

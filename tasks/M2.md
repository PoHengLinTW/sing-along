# M2 — Recording

**Goal:** Record a lossless take at the playhead while hearing the other tracks, keep it as a crash-safe local draft, line it up with the latency slider, and upload it.

**Exit criteria:** On desktop and iPhone, a user records a harmony take over existing tracks, aligns it by ear, uploads it, and another browser hears it in sync.

---

### M2-01 Mic setup, input device picker and headphone hint 📱
**Depends on:** M1-10
**Scope:** Request the mic with the PRD R2 constraints, let the user choose an input device, handle permission states, and show a headphone hint the first time.

**AC:**
- [x] `getUserMedia` uses `echoCancellation`, `noiseSuppression` and `autoGainControl` = `false`, and `channelCount: 1`.
- [x] An input picker lists the devices from `enumerateDevices()` (with labels shown after permission is granted). The choice is saved in localStorage and falls back to the default if that device is gone.
- [x] If permission is denied, a message explains how to allow the mic in the browser settings. If no mic is found, a clear message is shown.
- [x] A "Use headphones" hint appears before the first recording in this browser, with a "Don't show again" option.
- [ ] _(open: real-device check on desktop Chrome/Safari and iPhone Safari. `MicSetup` is not mounted in the project page yet; M2-04/M2-10 add the Record button and mount it, and the hint must then gate the first recording.)_

### M2-02 AudioWorklet recorder module
**Depends on:** M2-01
**Scope:** Port the M0 worklet into `apps/web/src/audio/recorder/`. It captures Float32 mono, sends chunks to the main thread, and supports a mute flag that replaces samples with zeros.

**AC:**
- [x] The recorder exposes `start()`, `stop()`, `setMuted(bool)` and an `onChunk` callback. Chunks cover about 1 s.
- [x] While muted, the take keeps its full length and the muted section is digital silence.
- [x] Recording runs at the `AudioContext` sample rate, and the rate is stored with the take.
- [x] The sample count of a 60 s take is within ±50 ms of 60 s.
- [ ] _(open: the sample-count and mute criteria are proven on the pure batcher only; confirm on a real mic/device during QA. The `?worker&url` worklet import is untested in a bundle until M2-04 imports the recorder.)_

### M2-03 Crash-safe draft storage (IndexedDB)
**Depends on:** M2-02
**Scope:** Store the draft's metadata and PCM chunks in IndexedDB (e.g. with the `idb` library) as they arrive, and recover unfinished drafts on load.

**AC:**
- [x] Each chunk is saved within about 1 s of being captured. The draft record holds projectId, startOffsetMs, sampleRate, createdAt, status (`recording` | `encoding` | `ready`), name and performer.
- [ ] After a reload or crash mid-recording, the project page offers the recovered draft with ≥ (elapsed − 2 s) of audio. _(open: `recoverInterrupted` and the store keep the audio across a reopen (tested); the project page does not show recovered drafts until M2-07.)_
- [x] Drafts are stored per project and listed only on their own project.
- [x] Unit tests (fake-indexeddb) cover saving, listing, recovering and deleting drafts.

### M2-04 Record at the playhead (engine integration) 📱
**Depends on:** M2-02, M2-03
**Scope:** Recording starts at the current playhead. If playback is stopped, pressing Record starts playback and recording together. Stop ends the take and pauses playback.

**AC:**
- [x] The take's `startOffsetMs` equals the playhead position at the first recorded sample, based on `AudioContext` time. The calculation is a unit-tested pure function.
- [ ] Other tracks keep playing during the recording with no glitches. _(open: needs a listening check on desktop and iPhone; the engine is untouched apart from an open-ended playhead.)_
- [x] Seeking and A–B looping are **disabled while recording**. The controls are greyed out with a tooltip.
- [x] Recording stops automatically at 10 min with a toast (PRD caps).
- [x] Each recording creates a new draft. Existing drafts aren't changed.

### M2-05 Live input waveform and level meter 📱
**Depends on:** M2-04
**Scope:** While recording, draw a live waveform in a "recording" lane that grows from the take's start offset in step with the playhead, plus an input level meter with a clipping warning.

**AC:**
- [x] The live waveform updates at ≥ 30 fps and lines up with the timeline position. _(Unit-tested: level blocks arrive 43+ times a second, one redraw per animation frame, and column placement is a pure function checked against the ruler maths. A visual check that the lane tracks the playhead is still worth doing by eye.)_
- [x] The level meter shows the input level in real time. A clipping warning appears when samples reach ≥ −0.1 dBFS and stays visible for 2 s.
- [x] The meter also works **before** recording (an "input check" mode) so the user can set their mic level.
- [ ] No noticeable CPU spike: recording and drawing together cause no audio glitches on the iPhone. _(open: needs the iPhone. The draw is limited to the visible viewport and one redraw per frame, which should keep it cheap.)_

### M2-06 FLAC encode worker (+ WAV fallback)
**Depends on:** M2-03
**Scope:** On Stop, a Web Worker reads the draft's chunks and encodes them to FLAC 16-bit mono with the encoder chosen in M0. If the encoder can't load, it produces WAV instead. It also computes peaks and duration.

**AC:**
- [x] Encoding runs in a worker, so the UI stays responsive, and shows a progress indicator.
- [x] If the WASM module fails to load, a WAV 16-bit mono file is produced and a notice says so. _(The encoder is the asm.js build, not WASM; any encoder failure takes the WAV path, unit-tested. Main-thread WAV is the last resort if the worker script itself cannot start.)_
- [x] The encoded blob, peaks, duration and MIME type are saved on the draft, and the status becomes `ready`. The raw chunks are then deleted to free space.
- [ ] A 4-minute take encodes in under 10 s on the iPhone. _(open: needs the iPhone. Desktop, built worker, 4-min 48 kHz take: 0.65 s Chromium 145, 0.73 s Firefox 146, 0.47 s WebKit 26; `spike/probe/m2-encode-worker.mjs`.)_
- [ ] The encoded output decodes and plays in Chrome, Safari and Firefox. _(open: `decodeAudioData` accepts the output in Playwright's Chromium 145, Firefox 146 and WebKit 26 (not real Safari); listen to a take in real Safari and on the iPhone.)_

### M2-07 Draft takes UI
**Depends on:** M2-06, M1-13
**Scope:** Drafts appear as their own lanes in the multitrack view, marked "Not uploaded." They can be played with the mix, mixed, renamed and discarded.

**AC:**
- [ ] Draft lanes look clearly different (e.g. dashed border plus a "Draft" badge) and sit below the uploaded tracks.
- [ ] A draft plays in the engine with the other tracks and has volume, mute and solo.
- [ ] The name defaults to "Take N". The performer is pre-filled from localStorage. Both can be edited.
- [ ] Discard opens `ConfirmDialog` ("This take exists only on this device."). After confirming, the draft is removed from IndexedDB.
- [ ] Several drafts can exist at once. Re-recording creates a new draft.

### M2-08 Latency offset slider 📱
**Depends on:** M2-07
**Scope:** Every track and draft gets a latency offset control. The waveform moves live, and the value is saved (to the server for tracks, to IndexedDB for drafts).

**AC:**
- [ ] The slider covers ±1000 ms in 1 ms steps. Arrow keys nudge by 1 ms and Shift+arrow by 10 ms. A number field allows exact entry. A reset button returns it to 0.
- [ ] The waveform shifts immediately while dragging. The audio uses the new offset on the next play or seek, or is rescheduled live (per M1-10).
- [ ] For uploaded tracks, the value is PATCHed after about 500 ms without changes. For drafts, it's saved to IndexedDB and included in the upload.
- [ ] A 2-second "loop around here" preview button plays the 4 s around the playhead, to make alignment by ear easier.

### M2-09 Upload a draft
**Depends on:** M2-07, M1-11
**Scope:** Upload a ready draft through the existing upload pipeline, with `source = recording`.

**AC:**
- [ ] Upload sends the encoded blob, peaks, duration, `startOffsetMs`, `latencyOffsetMs`, name, performer and labels.
- [ ] Progress is shown. On success, the draft is removed from IndexedDB and the new track appears in its place with the same mix settings.
- [ ] On failure (network or server error), the draft is kept and a **Retry** option is shown.
- [ ] Refreshing the page mid-upload keeps the draft, and it can be uploaded again.

### M2-10 Record and mic-mute controls, shortcuts, leave guard
**Depends on:** M2-04
**Scope:** Record/Stop and mic-mute buttons in the transport bar, the R and M shortcuts, and a `beforeunload` warning while recording.

**AC:**
- [ ] The Record button shows a clear recording state (red, with elapsed time). R toggles recording. M toggles mic mute, and the muted state is clearly visible.
- [ ] M works only while recording or input-checking. Otherwise it does nothing.
- [ ] Shortcuts are ignored while typing in text inputs.
- [ ] Closing or reloading the tab during a recording triggers the browser's "Leave site?" prompt. No prompt appears when not recording.

### M2-11 Cross-device recording test pass 📱
**Depends on:** M2-01 … M2-10
**Scope:** An end-to-end manual test of recording on the target devices, with the problems found fixed or ticketed.

**AC:**
- [ ] Record → align → upload → play in another browser works on desktop Chrome, desktop Safari, iPhone Safari and Android Chrome.
- [ ] Tested with wired headphones and with Bluetooth headphones. Bluetooth latency is noted in the README as a known issue.
- [ ] Each problem found is fixed or filed as a follow-up task.
- [ ] Success criterion 2 is checked: after aligning a take once, it stays in sync over 5 repeated plays.

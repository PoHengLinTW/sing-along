# M4 — PWA and Mobile

**Goal:** Make the app installable, usable on phones with a dedicated layout, and able to work offline for projects the user chooses.

**Exit criteria:** All three PRD success criteria are met. In particular, the app is installed on an iPhone and a desktop, and a project marked offline can be practiced and recorded in airplane mode.

---

### M4-01 PWA manifest, icons and app-shell service worker
**Depends on:** M3-06
**Scope:** `vite-plugin-pwa` with a manifest, icons, a precached app shell and a prompt when an update is available.

**AC:**
- [ ] The manifest has a name, short name, theme and background colors, `display: standalone`, and icons at 192, 512 and maskable 512, plus an Apple touch icon.
- [ ] Lighthouse PWA/installability checks pass on the production build.
- [ ] After the first visit, the app shell loads with the network disabled (it shows the app with an "offline" banner, not the browser's error page).
- [ ] When a new version is deployed, users see "New version available — Reload." The app never reloads by itself mid-recording.
- [ ] API and presigned audio URLs are **not** precached by the service worker.

### M4-02 iOS audio and install handling 📱
**Depends on:** M4-01
**Scope:** Handle iOS quirks: unlocking the AudioContext, recovering from interruptions (phone calls, going to the background), and a hint to add the app to the home screen.

**AC:**
- [ ] The first tap anywhere unlocks or resumes the `AudioContext`. Playback works in both the Safari tab and the installed PWA.
- [ ] After going to the background and coming back (or after an interruption), the app detects a suspended or interrupted context and shows "Tap to resume audio." No silent failure.
- [ ] A recording is stopped cleanly and saved as a draft if the app goes to the background.
- [ ] iOS Safari (not installed) shows a dismissible "Add to Home Screen for the best experience" hint with instructions.

### M4-03 Audio cache by track ID
**Depends on:** M1-10
**Scope:** A Cache API wrapper that stores audio responses under the key `/audio/<trackId>` (not the presigned URL). The engine's loader checks the cache first.

**AC:**
- [ ] Opening a project a second time loads its audio from the cache with **zero** requests to R2 (confirmed in the DevTools network tab).
- [ ] The cache key doesn't depend on presigned URL expiry.
- [ ] Deleting a track (by this user) removes its cache entry. Tracks deleted by others are removed when the project's track list no longer contains them.
- [ ] Unit tests cover the cache wrapper (mocked Cache API).

### M4-04 Per-project "Make available offline" 📱
**Depends on:** M4-03
**Scope:** A per-project toggle that downloads and pins the project's metadata and all of its audio. It shows the size and progress and can be removed.

**AC:**
- [ ] The toggle shows the estimated size before downloading ("≈ 135 MB") and progress while downloading. It can be cancelled.
- [ ] `navigator.storage.persist()` is requested when the first project is made available offline. The result is shown ("Storage may be cleared by the browser" if refused).
- [ ] The project's metadata snapshot is stored so the project page renders fully offline.
- [ ] Offline projects show a badge on the home page and project page. "Remove offline copy" frees the space with no confirmation.
- [ ] Tracks added by others later are downloaded the next time the project is opened online.
- [ ] If the device runs out of storage, a clear error is shown and the partial download is rolled back.

### M4-05 Offline mode: read-only UX
**Depends on:** M4-04
**Scope:** Detect online and offline status, serve cached data, and turn off mutating actions while offline.

**AC:**
- [ ] An "Offline" banner appears within 2 s of losing the connection and disappears when the connection returns.
- [ ] Offline, the home page lists the offline projects only, under a note "Showing offline projects."
- [ ] In an offline project, playback, mixing, looping, the latency slider (saved locally, synced when back online) and **recording** all work.
- [ ] Create, edit, delete, upload and reorder are disabled offline, with the tooltip "Requires connection."
- [ ] An offline project opened in airplane mode on the iPhone works end to end (play, record, save draft).

### M4-06 Drafts badge and upload queue
**Depends on:** M2-09, M4-05
**Scope:** A global indicator for drafts that haven't been uploaded, and a way to upload them once back online.

**AC:**
- [ ] The app header shows "N drafts not uploaded." Clicking it lists the drafts grouped by project, with links.
- [ ] When the connection returns, a toast offers "Upload N drafts now?" Uploads never start automatically without the user confirming (PRD R6).
- [ ] "Upload all" uploads the drafts one at a time with progress. Failures stay queued with a retry option.

### M4-07 Responsive phone layout: overview and track list 📱
**Depends on:** M1-12, M1-13
**Scope:** At widths under 768 px, show a compact overview waveform plus a track list in place of the full multitrack timeline.

**AC:**
- [ ] Under 768 px: an overview waveform across the full song (a mix of the peaks, or the backing track) with a playhead and loop region. Tapping or dragging on it seeks.
- [ ] Each track row shows the name, label chips, a volume slider and mute/solo, with touch targets of at least 44×44 px.
- [ ] No horizontal page scrolling at 360 px wide.
- [ ] Desktop and tablet (≥ 768 px) layouts are unchanged.

### M4-08 Phone transport bar and track detail sheet 📱
**Depends on:** M4-07, M2-10
**Scope:** A fixed bottom transport bar with large buttons, and a bottom sheet per track with its waveform and latency slider.

**AC:**
- [ ] The bottom bar shows restart, −10, play/pause, +10, record and mic mute, with each button ≥ 56 px and respecting the safe-area insets (the iPhone home indicator).
- [ ] The current and total time appear above the bar.
- [ ] Tapping a track opens a bottom sheet with its waveform (zoomable), the latency slider, name/performer editing, labels and delete.
- [ ] The sheet closes by swiping down or tapping outside it.

### M4-09 Touch interactions 📱
**Depends on:** M4-07
**Scope:** Make seeking, loop editing and reordering usable by touch.

**AC:**
- [ ] Dragging on the overview seeks without scrolling the page (`touch-action` handled correctly).
- [ ] Long-pressing and dragging on the overview creates the A–B loop, and the edge handles can be dragged.
- [ ] Track rows can be reordered with a drag handle on touch.
- [ ] Pinch-to-zoom in the track detail sheet waveform works, and zooming the page is prevented only inside the waveform.

### M4-10 Success-criteria verification 📱
**Depends on:** all M4 tasks
**Scope:** Final acceptance against the PRD success criteria on real devices, in production.

**AC:**
- [ ] **SC1:** The group practices a real song with at least 1 backing track and at least 3 harmony takes recorded in the app.
- [ ] **SC2:** Takes aligned once stay in sync by ear across 5 plays on 2 different devices.
- [ ] **SC3:** Installed as a PWA on at least one iPhone and one desktop. An offline project plays and records in airplane mode.
- [ ] Any problems found are fixed or filed. The PRD status is updated to "v1 shipped."

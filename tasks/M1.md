# M1 — Core Player

**Goal:** A working multitrack player built from **uploaded** files: project and track CRUD, synced playback, waveforms, mixer, transport and labels. It runs locally against Postgres and RustFS.

**Exit criteria:** Locally, a user can create a project, upload several tracks with labels, play them in sync, mix them, loop a section and seek using the waveform. Deletes ask for confirmation.

### M1-03 Database schema and label seed
**Depends on:** M1-02
**Scope:** Tables `projects`, `tracks`, `labels`, `track_labels`. Tracks have `status` (`pending` | `active`) for the upload-confirm flow. Seed the preset labels.

**AC:**
- [x] Every field listed in PRD T2 exists on `tracks`, plus `status`. `peaks` is JSONB.
- [x] `projects` has `title` (not null), `artist`, `notes`, `created_at`, `updated_at`.
- [x] `labels` has a unique `name`, a `color` and an `is_preset` flag. The 12 presets from PRD L2 are seeded **idempotently** (running the seed twice creates no duplicates).
- [x] Deleting a project cascades to its tracks and `track_labels`. Deleting a track cascades to its `track_labels`.
- [x] The migration runs cleanly on an empty database.

### M1-04 Projects API
**Depends on:** M1-03
**Scope:** `GET /api/projects`, `POST /api/projects`, `GET/PATCH/DELETE /api/projects/:id`, validated with zod schemas from `packages/shared`.

**AC:**
- [x] The list returns id, title, artist, active track count and `updated_at`, newest first.

### M1-05 Storage service and presigned upload/confirm flow
**Depends on:** M1-03
**Scope:** An S3-compatible client (works with both R2 and RustFS). Endpoints:
- `POST /api/projects/:id/tracks/upload-url` creates a pending track and returns a presigned PUT.
- `POST /api/tracks/:id/confirm` activates the track.
- `GET /api/tracks/:id/audio-url` returns a presigned GET.

**AC:**
- [x] The upload-url request takes `{name, performer, labels, mimeType, sizeBytes, durationMs, startOffsetMs, source, peaks}`. It rejects MIME types not in the allowed list (PRD T1) with 415.
- [x] The presigned PUT is signed with the exact `Content-Type` and `Content-Length`. A PUT with a different size is rejected by storage (checked against RustFS).
- [x] The object key format is `projects/<projectId>/tracks/<trackId>` plus the file extension.
- [x] Confirm checks the object with HEAD. If it's missing or the size differs, confirm returns 400 and deletes the object. Otherwise the track becomes `active`.
- [ ] Presigned URLs expire after 15 min (configurable). _(open: default 900 s and env var done; a non-default TTL is not tested)_
- [x] Unit tests use a mocked storage client.

### M1-06 Tracks and labels API
**Depends on:** M1-05
**Scope:**
- `PATCH /api/tracks/:id` (name, performer, labels, start/latency offsets)
- `DELETE /api/tracks/:id`
- `PUT /api/projects/:id/track-order`
- `GET/POST /api/labels`

**AC:**
- [x] `PATCH` accepts partial updates. Labels are replaced as a set. Offsets are integers within ±600 000 ms.
- [x] `DELETE` removes the DB row **and** the storage object, and returns 204. It's idempotent: a second call returns 404, never 500.
- [ ] Track order takes the full list of track ids. It rejects ids from another project or a partial list with 400, and saves `sort_order` in one transaction. _(open: validation tested; atomicity of the single transaction is not tested)_
- [x] `POST /labels` creates a custom label (trimmed, 1–30 characters, compared case-insensitively). Creating an existing name returns the existing label.
- [x] Every track change updates the parent project's `updated_at`.
- [x] Unit tests cover the above.

### M1-10 Audio engine and transport store
**Depends on:** M1-01
**Scope:** Port the M0 engine into `apps/web/src/audio/`:
- An `AudioEngine` class that loads buffers, handles play, pause and seek, gives each track a GainNode (volume, mute, solo), schedules tracks by `start_offset_ms + latency_offset_ms`, and handles the A–B loop.
- A Zustand store for transport state (playing, position, duration, loop).

**AC:**
- [x] A **pure function** (unit tested) calculates, for a given playhead and set of tracks, which tracks start when and at what offset into their buffers. Covered cases: negative offsets, tracks starting after the playhead, and a playhead past a track's end.
- [x] Solo logic is a unit-tested pure function: if any track is soloed, only soloed tracks are audible; mute always wins.
- [ ] Changing volume, mute or solo during playback takes effect within 50 ms without restarting playback. _(open: no-restart and <= 50 ms smoothing tested on a fake clock; real latency not measured)_
- [x] Changing an offset during playback reschedules the affected track only.
- [x] Position updates at least 30 times per second for the UI, without re-rendering the whole React tree (subscription through a selector).
- [x] Project duration = the maximum over all tracks of (offset + duration).
- [ ] The `AudioContext` is created or resumed on the first user gesture. _(open: lazy context and resume-on-play tested; the first-gesture handler itself is untested)_

### M1-11 Upload track flow
**Depends on:** M1-05, M1-06, M1-10
**Scope:** File picker and drag-and-drop on the project page. The client checks the file, decodes it for duration and peaks, and then does upload-url → PUT with progress → confirm.

**AC:**
- [x] Accepts the PRD T1 formats. Anything else is rejected before upload with "Unsupported format."
- [x] Before uploading, the client computes `durationMs` and peaks (about 100 peaks per second of audio) with a pure, unit-tested peaks function. The peaks JSON for a 10-min track is ≤ 500 KB.
- [x] An upload form collects the name (defaults to the file name), performer (pre-filled from localStorage) and labels.
- [x] Progress is shown as a percentage. Cancelling aborts the PUT, and the pending track is left for cleanup.
- [x] On success the new track appears in the view without a page reload (the query is invalidated).
- [x] Several files dropped at once upload one after another, each with its own form or defaults.

### M1-12 Multitrack waveform view
**Depends on:** M1-10, M1-11
**Scope:** Render each track's waveform from its stored peaks (wavesurfer.js, per the M0-07 decision), placed at its offset on a shared timeline with a playhead that follows the engine.

**AC:**
- [ ] Waveforms appear before the audio has finished downloading (they come from peaks only). A per-track loading indicator shows until the buffer is ready. _(open: tested with wavesurfer mocked; real render seen once in Chromium)_
- [x] A track is shifted horizontally by `start_offset_ms + latency_offset_ms`.
- [ ] The playhead moves smoothly while playing and matches the engine position within 1 frame. _(open: playhead is written straight to the DOM; smoothness not judged visually)_
- [x] Clicking or dragging on the timeline or ruler seeks. Seeking while playing continues playback from the new point.
- [x] Zoom in and out (buttons and Ctrl/Cmd + scroll) and horizontal scrolling. The view auto-follows the playhead while playing unless the user has scrolled away.
- [x] A time ruler shows mm:ss marks that adapt to the zoom level.

### M1-15 A–B loop
**Depends on:** M1-12, M1-14
**Scope:** Define a loop region by dragging on the ruler, or with "Set A" and "Set B" buttons at the playhead. Toggle looping and clear the loop.

**AC:**
- [x] Dragging on the ruler creates a highlighted region. Its edges can be dragged to adjust it.
- [ ] With looping on, reaching B jumps back to A with a gap of ≤ 50 ms and no stuck notes or buffer glitches. _(open: gap 0 on a fake clock and in a Chromium run; not heard, and hidden-tab timer throttling is unverified)_
- [x] Seeking outside the loop while looping is on: playback continues to B only if the playhead is before B. Otherwise the loop is ignored until the playhead re-enters it.
- [x] B must be after A (at least 0.5 s apart). Clearing removes the region.
- [x] Unit tests cover the loop boundary logic.
